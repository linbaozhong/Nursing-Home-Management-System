# 敬老院管理系统 · 家属端小程序《移动端复刻方案》

> 文档版本：v1.0
> 生成日期：2026-08-19
> 适用项目：`mp-c`（微信小程序，uni-app + Vue3）
> 目标用户：**入住老人的家属**（子女/监护人）
> 后端：复用现有 `http://<后端>/api/...` 接口（以"家属视角+被绑定老人"为数据范围）

---

## 一、方案概述

家属端小程序与员工端**定位完全不同**：它不是"后台精简版"，而是围绕**单个/多个被绑定老人**的**服务与关怀平台**。PC 后台里很多"管理视角"的页面（楼栋维护、员工管理、来源渠道等）对家属无意义，**需重新设计而非照搬**。

核心设计原则：

- **以"我的家人"为入口**：登录后先选要查看的老人（一个家属可绑定多位老人）；
- **分页全部取消**（按用户要求），列表改为"时间倒序 + 分类切换 + 无限滚动/全量"；
- **信息呈现重情感与透明**：护理记录、消费账单、餐饮、活动照片，让家属"看得见、放心"；
- **交互轻量**：少表单、多查看；需要家属操作的主要是"在线点餐""充值""留言/预约探视"。

### 1.1 家属端功能矩阵（基于 PC 接口可复用部分）

| 功能 | 家属价值 | 可复用 PC 接口 | 说明 |
|---|---|---|---|
| 登录 / 绑定家人 | 入口 | `account.login` + 新增"家属绑定" | 自研账号体系；需后端提供"家属-老人绑定"接口（PC 未直接提供，需新增或复用） |
| 家人概览（首页） | 一屏看老人状态 | `elderRecord.getElderById` `getElderRecordById` | 老人头像、房间、护理等级、今日状态 |
| 护理记录 | 透明护理 | `nurseReserve.*`（查执行记录） | 按日期查看护理项目与执行情况 |
| 消费账单 | 透明消费 | `consume.pageConsumeByKey` + `depositRecharge.*` | 账单明细 + 账户余额 + 在线充值入口 |
| 餐饮查看 / 点餐 | 关怀饮食 | `order.*` `dishes.*` `cateringSet.*` | 查看套餐；家属代点餐或查看在吃套餐 |
| 来访/探视预约 | 方便探视 | `visit.addVisit` | 家属预约探视时间（替代现场登记） |
| 外出告知 | 知情 | `outward.*`（查） | 查看老人外出/返回记录（只读） |
| 事故/异常通知 | 及时知情 | `accident.*`（查） | 查看记录（只读）+ 必要时推送 |
| 我的 | 账号 | `account.editPass` `logout` | 修改密码、解绑、退出 |

> **需后端新增/确认的接口**（PC 未直接提供）：
> 1. 家属注册与"绑定老人"接口（凭老人姓名+身份证后几位+手机号校验）；
> 2. 家属视角的数据范围过滤（只能看自己绑定的老人）；
> 3. 在线充值支付回调（微信支付）；
> 4. （可选）消息推送（事故/外出/账单）。

## 三、交互改造点（家属端）

### 3.1 以"家人"为中心的导航
- 登录后若有多个绑定老人，先进入 `family/choose` 选人；之后所有页面顶部显示"当前家人"可切换。
- TabBar 四项固定，不依赖 PC 的权限树（家属权限天然单一）。

### 3.2 列表取消分页
- 账单、护理记录等长列表**取消分页**，按时间倒序全量加载（或 `size` 取大），用「日期分段标题」组织，配合下拉刷新。

### 3.3 信息可视化（情感化）
- 首页用**大卡片**呈现老人状态（在住/外出/异常），配房间、护理等级、今日餐饮图标；
- 护理记录用**时间轴（Timeline）** 替代表格；
- 账单用**月度分组 + 收支汇总头**替代流水表。

### 3.4 点餐交互
- 家属代点：展示可选菜品/套餐（卡片勾选）→ 提交 `order.addOrder`，指定送餐时间；
- 不展示 PC 的"送餐人员下拉"等内部字段，仅保留对家属有意义的信息。

### 3.5 探视预约替代现场登记
- PC 来访登记是"门岗现场登记"，家属端改为**提前预约**：选日期+时段+来访人数 → `visit.addVisit`，到院后由员工端确认（`visit.recordLeave` 仍由员工操作）。

### 3.6 安全与隐私
- 所有写操作（充值、点餐、预约）需二次确认；
- 异常记录（事故）默认对家属**仅展示摘要+处理状态**，细节由院方控制。

## 四、技术栈与目录结构规划

### 4.1 技术栈
- **框架**：uni-app（Vue3 + `<script setup>` + TS），与员工端完全一致，便于复用组件
- **状态管理**：Pinia（`auth` 存 token/家属信息、`family` 存当前选中老人及绑定列表）
- **网络**：与员工端共用的 `uni.request` 封装（建议抽成内部 npm 包或复制一份 `utils/request.ts`）
- **UI**：`uni-ui` + 自定义（时间轴、账单卡片、家人切换器）；图表可省略
- **支付**：微信小程序 `wx.requestPayment`（充值）
- **登录**：自研账号体系 + 家属绑定；可加"微信一键登录"降低注册门槛（需后端配合 openid 绑定）

## 五、MVP 落地建议（家属端）

1. **先与后端确认"家属绑定 + 数据范围"接口**（这是家属端能否成立的关键前置，PC 现有接口未覆盖）。
2. **第一步**：登录/注册绑定 + 家人选择 + 首页概览（只读展示老人状态）。
3. **第二步**：护理记录（时间轴）、消费账单（分组卡片）、餐饮查看——建立"透明信任"。
4. **第三步**：在线点餐、探视预约、账户充值（接微信支付）——形成家属可操作闭环。
5. **第四步**：异常通知推送、多人绑定管理、微信一键登录。

> 注意：家属端**不要复用员工端的写接口越权**，所有数据必须走"家属视角过滤"后的接口；PC 现有接口需后端做一层家属身份校验与数据隔离。
