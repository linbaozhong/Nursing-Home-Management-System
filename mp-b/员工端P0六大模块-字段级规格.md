## 0. 全局规范

### 0.1 接口约定
| 项 | 约定 |
|---|---|
| BaseURL | `https://<域名>/v1`（Go 路由全带 `/v1` 前缀，**非**老系统 `/api`） |
| 鉴权 | 免登录白名单：`/account/login`、`/account/wxLogin`、`/account/sendCode`、`/account/forget`、`/tenant/register`；其余全部需 `Authorization: Bearer <token>`（`lib.AuthMiddleware`） |
| 统一响应 | `Result { code:int, msg:string, data:object }`；分页数据在 `data` 内为 `PageResult { page_num, page_size, pages, size, total, list }` |
| 错误 | `code != 0` 时 toast `msg`；`code == 401` 清登录态跳登录页 |
| 多租户上下文 | token 格式 `userID[_tenantID[_memberID]]`，中间件解析后注入请求上下文；**旧 token（无租户段）视为平台租户成员**，鉴权通过但建议重新登录刷新 |
| 时间 | `time.Time` → 字符串 `2006-01-02 15:04:05`，移动端展示格式化 `MM-DD HH:mm` |
| 金额 | `types.Money`（`pay_amount`、`price`、`total_amount`、`really_amount` 等）→ JSON 数字（元），前端一律 `¥xx.xx`，禁止 `toFixed` 丢精度，建议分计算/BigInt |
| 分页 | **P0 列表全部取消分页**：请求 `page_num=1&page_size=200`，前端本地全量搜索/筛选（见 §7） |

### 0.2 通用组件
> 业务组件全部落位 `admin/components/`，props / 事件 / 状态字段级定义见 **§9 组件契约**。本节为速览，契约与实现状态以 §9 为准。

1. **WizardForm 向导高阶模板**（外出/来访/事故/点餐新增复用）：Step 指示器 + 上一步/下一步/提交，见 §9.2
2. **ElderSearch 长者搜索器**（外出/来访/事故/点餐/档案共用）
   - 触发：列表页顶部搜索框、或向导 Step1 的"选择老人"入口
   - 数据源：`GET /elderRecord/pageSearchElderByKey`（分页 200，本地过滤）
   - 弹层半屏：搜索框（`name`）+ 列表项 `[姓名] 身份证尾4位 / 电话 / 入住状态`
   - 返回选中对象 `{ id, name, id_num, sex, phone, address, check_flag }`，契约见 §9.3
3. **StaffSearch 员工搜索器**（事故-护工、送餐人员）
   - 数据源：`GET /reserve/pageSearchStaffByKey`（`{page_num,page_size,name?,phone?}` → `{id,name,phone}`）
   - 送餐人员另可用无参全量 `GET /nurseReserve/listNurseStaff` → `{id,name,phone}`
   - 契约见 §9.4
4. **DateTimePicker**：`picker mode="date"` + `mode="time"` 组合，输出 `yyyy-MM-dd HH:mm`；计划返回时间校验 > 外出时间，契约见 §9.5
5. **ImageUploader 图片上传**：`uni.chooseMedia`（最多 9 张）→ base64 → `POST /file/uploadImage`（JSON `{ module, file }`）→ 存返回 URL 字符串；支持预览/删除，契约见 §9.5
6. **StatusTag 状态标签**：色板见各模块与 §9.6
7. **DishesPicker 菜品选择器**（点餐）、**ContactQuickFill 联系人快捷填充**（外出）、**SectionCard 详情分区块**：见 §9.7~§9.9

> 注：P0 已实现组件见 §9.0 实现状态表；`ListPage`/`SectionCard` 尚未抽组件，列表页/详情分区块暂由页面内联。

## 1. 登录 · 权限 · 多租户（`pages/login`、`pages/register`、`pages/switch-tenant`、`pages/join-tenant`、`pages/mine`）

### 1.1 页面
| 页面 | 路径 | 说明 |
|---|---|---|
| 登录 | `pages/login/login` | **微信一键登录（主入口）** + 账号密码（备用）；已登录态自动进工作台 |
| 创建企业 | `pages/register/register` | 3 步向导：①企业信息 ②管理员账号 ③微信绑定确认；提交 `POST /tenant/register` 后直接进入工作台 |
| 选择企业 | `pages/switch-tenant/switch` | `GET /tenant/myTenants` 企业列表，点选 `POST /tenant/switchTenant` 切换；空态引导创建企业 |
| 加入企业 | `pages/join-tenant/join` | 输入邀请码 `POST /tenant/joinMember` |
| 个人中心 | `pages/mine/index` | 头像/姓名/手机号/修改密码/退出登录 |
| 修改密码 | `pages/mine/edit-pass` | `POST /account/edit` |

### 1.2 接口契约
| 接口 | 方法 | 鉴权 | 请求 | 响应 |
|---|---|---|---|---|
| `/account/login` | POST | 免 | `{ phone*, pass*, code? }` | `LoginUserResp` |
| `/account/wxLogin` | POST | 免 | `{ code* }` | `WxLoginResp { need_bind, token, user?, tenants[] }` |
| `/account/edit` | POST | 需 | `{ id*, old_pass*, new_pass* }` | `EmptyResp` |
| `/account/sendCode` | POST | 免 | `{ phone* }` | `EmptyResp`（备用） |
| `/account/logout` | GET | 需 | `-` | `EmptyResp` |
| `/tenant/register` | POST | 免 | `RegisterTenantQuery` | `LoginUserResp` |
| `/tenant/myTenants` | GET | 需 | `-` | `UserTenantListResp { tenants[]=TenantResp, current }` |
| `/tenant/switchTenant` | POST | 需 | `{ tenant_id* }` | `LoginUserResp`（重新签发 token） |
| `/tenant/joinMember` | POST | 需 | `{ invite_code* }` | `LoginUserResp` |
| `/tenant/inviteMember` | POST | 需（租户管理员） | `{ tenant_id*, phone*, role_id* }` | `MemberResp` |
| `/tenant/open` | POST | 需（平台管理员） | `{ id* }` | `EmptyResp` |
| `/tenant/lock` | POST | 需（平台管理员） | `{ id* }` | `EmptyResp` |

**LoginUserResp**（`/account/login`、`/tenant/register`、`/tenant/switchTenant` 均返回）：
```
{
  id: int64,             // 全局用户 id
  name, avator, phone, pass,
  tenant_id: int64,      // 当前租户编号
  member_id: int64,      // 当前成员编号
  role_id: int64,        // 当前角色编号
  need_bind: bool,       // true=需选择/绑定企业（前端据此分流）
  auth_id_list: int64[],
  auth_url_list: string[],
  tenants: TenantResp[],   // 已绑定企业列表（多企业时返回）
  token
}
```

**TenantResp**：`id, name, logo, contact_name, contact_phone, plan, status(int8: 0试用中/1正式/2锁定), trial_start, trial_end`
**WxLoginResp**：`need_bind, token, user(LoginUserResp|null), tenants(TenantResp[])`
**MemberResp**：`id, user_id, name, phone, role_id, status(int8: 0在职/1离职), auth_urls[]`

### 1.3 登录分流（need_bind 智能分流）
```
打开登录页 pages/login
 ├─ 已登录（token 非空）──> reLaunch 工作台 pages/index
 └─ 未登录：uni.login 取 code → POST /account/wxLogin（静默尝试）
      ├─ need_bind=false 且 user!=null ──> setLoginUser → 工作台（唯一企业自动登录）
      ├─ need_bind=true 且 tenants>0  ──> navigateTo pages/switch-tenant 选择企业
      └─ need_bind=true 且 tenants 空 ──> navigateTo pages/register 创建企业（新用户）
账号密码登录 /account/login 复用同一分流逻辑；登录页"没有企业？立即创建企业"→ register
```
- `pages/switch-tenant`：`GET /tenant/myTenants` 渲染企业卡片（名称/状态：试用中/正式/已锁定）→ 点击 `POST /tenant/switchTenant { tenant_id }` → `setLoginUser` → 工作台
- `pages/register`：3 步向导 → `POST /tenant/register`（携带 `wx_code` 完成微信绑定）→ 成功后 `setLoginUser` → 工作台；注册即开通 30 天免费试用（`TrialDays=30`），试用结束自动锁定
- `pages/join-tenant`：输入邀请码 → `POST /tenant/joinMember { invite_code }` → `setLoginUser` → 工作台

### 1.4 多租户数据落地（utils/auth.ts）
| Storage key | 内容 | 说明 |
|---|---|---|
| `token` | 后端签发 token | 请求头 `Authorization: Bearer <token>`（`utils/request.ts` 自动注入） |
| `login_user` | `LoginUser` 全量 | `getLoginUser()`；`setLoginUser(user)` 同时写 `token` 与 `current_tenant` |
| `current_tenant` | 当前租户 id | `getCurrentTenantId()` / `setCurrentTenantId()`；记住上次选择 |

- `clearAuth()`：三键全清（退出登录）
- 权限判断：`canAccess(module)`（`auth_url_list` 精确匹配）、`accessibleModules()` 过滤、`hasAuth(authId)`（`auth_id_list` 匹配）

### 1.5 权限映射（auth_url_list 驱动，已固化）
- 首页工作台功能入口 / 模块 **按 `auth_url_list` 显隐**：

| 模块 | 权限 url（后端 auth.url） | 前端 ModuleKey | 落地 |
|---|---|---|---|
| 长者档案 | `/people/old` | `elder` | TabBar / 工作台 |
| 外出登记 | `/check-in/leave` | `leave` | TabBar / 工作台 |
| 来访登记 | `/check-in/visit` | `visit` | 工作台入口 |
| 事故登记 | `/check-in/accident` | `accident` | 工作台入口 |
| 点餐 | `/food/order` | `order` | TabBar / 工作台 |

- 前端实现：`utils/auth.ts` 的 `canAccess(module)` + `accessibleModules()`；`pages/index` 工作台按权限渲染入口，头部展示「当前企业名」（从 `tenants` 匹配 `tenant_id`）；无权限时显示"暂无可用功能权限"。
- 角色约定：token 中角色标识 `tenant`（租户成员）/ `platform`（平台管理员）；平台管理员可调 `/tenant/open`、`/tenant/lock`。
- 注意：uni-app-x **原生 tabBar 无法登录后动态增删**，故 TabBar 4 项固定（档案/外出/点餐/我的），工作台 `pages/index` 为登录落地页（非 Tab），来访/事故作为工作台功能入口（`navigateTo`）按权限显隐。

## 2. 外出登记（`pages/leave`）

### 2.1 页面结构
| 页面 | 路径 | 说明 |
|---|---|---|
| 列表 | `pages/leave/list` | 全量加载 + 本地筛选 |
| 新增向导 | `pages/leave/edit` | 2 步：①选老人 ②陪同人+时间 |
| 详情/操作 | `pages/leave/detail` | 状态化按钮区 |

### 2.2 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/outward/pageOutwardByKey` | GET | `page_num,page_size,elder_name?,chaperone_type?,start_time?,end_time?` | 分页 `list[] = PageOutwardByKeyResp` |
| `/outward/addOutward` | POST | `AddOutwardQuery` | `EmptyResp` |
| `/outward/getOutwardById` | GET | `{ id }` | `GetOutwardByIDResp` |
| `/outward/editOutward` | POST | `EditOutwardQuery` | `EmptyResp` |
| `/outward/delayReturn` | POST | `{ id*, plan_return_date* }` | `EmptyResp` |
| `/outward/recordReturn` | POST | `{ id*, real_return_date* }` | `EmptyResp` |
| `/outward/deleteOutward` | POST | `{ id }` | `EmptyResp` |

**PageOutwardByKeyResp**：`id, elder_name, chaperone_name, chaperone_phone, chaperone_type, outward_date, plan_return_date, real_return_date`
**GetOutwardByIDResp**：`id, elder_name, chaperone_name, chaperone_phone, chaperone_type, outward_date, plan_return_date`
**AddOutwardQuery**（编辑=同字段+`id`）：`elder_id*, chaperone_name*, chaperone_phone*, chaperone_type*, outward_date*, plan_return_date*`

### 2.3 列表页
- **搜索区**：老人姓名输入框（本地过滤 `elder_name`）
- **筛选**：`chaperone_type` 分段器 `全部 / 护工 / 家属`；时间范围（可选，本地过滤 `outward_date`）
- **卡片**（一行一卡）：
  - 左侧：`老人姓名`（加粗）+ 状态 Tag
  - 右侧：`外出时间` → `计划返回时间`
  - 底部：`陪同人：xxx(家属/护工) · 138xxxx`，未返回且超时的显示红色"已超时"角标
- **状态派生逻辑**（后端不返回状态字段，前端本地推导）：

| 状态 | 判定 | Tag 色 |
|---|---|---|
| 外出中 | `real_return_date` 为空且未超时 | 蓝 |
| 已超时 | `real_return_date` 为空且 `now > plan_return_date` | 红 |
| 已返回 | `real_return_date` 非空 | 绿 |
- **空态**：无数据 → 插画 + "暂无外出记录" + 去登记按钮

### 2.4 新增向导（2 步）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ①选老人 | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ②陪同人 | 姓名 | `chaperone_name` | string | ✅ | input | 必填 ≤20 字 |
| ②陪同人 | 电话 | `chaperone_phone` | string | ✅ | input type=number | 11 位手机号 |
| ②陪同人 | 类型 | `chaperone_type` | string | ✅ | radio | 枚举 `护工/家属` |
| ②时间 | 外出时间 | `outward_date` | datetime | ✅ | DateTimePicker | 必填 |
| ②时间 | 计划返回 | `plan_return_date` | datetime | ✅ | DateTimePicker | 必填，> outward_date |

- 陪同人**快捷填充**：`ContactQuickFill` 复用 `GET /elderRecord/pageSearchEmergencyContactByKey?elder_id=`，点击自动回填姓名/电话并置 `chaperone_type=家属`（见 §9.8）
- 提交：`addOutward` → 成功提示 → 返回列表刷新（新记录置顶）

### 2.5 详情/操作状态机
```
已返回(real_return_date!=空) ──> 仅"删除"可操作
外出中 ──> [延期返回] [登记返回] [删除]
```
- **延期返回**：弹窗 DateTimePicker（新 `plan_return_date`，默认当前时间+1h，必须晚于原计划）→ `delayReturn`
- **登记返回**：确认弹窗"确认该老人已返回？"（时间默认 now，可改）→ `recordReturn`
- **删除**：二次确认弹窗 → `deleteOutward`；删除后卡片消失

## 3. 来访登记（`pages/visitor`）

### 3.1 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/visit/pageVisitByKey` | GET | `page_num,page_size,elder_name?,visit_name?,visit_phone?,visit_flag?` | 分页 `list[] = PageVisitByKeyResp` |

**AddVisitQuery**（编辑=同字段+`id`）：`elder_id*, name*, phone*, relation*, visit_date*, visit_num*`

### 3.2 列表页
- **搜索**：老人姓名（本地过滤 `elder_name`）
- **筛选**：`visit_flag` 分段器 `全部 / 在院(0) / 已离开(1)`——后端筛选直接传 `visit_flag`
- **卡片**：
  - 头部：`老人姓名` + Tag（在院=绿 / 已离开=灰）
  - 主体：`来访者：姓名(关系) · 138xxxx`；`人数 xN`
  - 底部：`来访时间`（已离开时追加 `离开时间`）
- **列表页快捷操作**：未离开卡片提供 `[登记离开]` 按钮（列表页直达，不必进详情）

### 3.3 新增向导（2 步）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ① | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ② | 来访者姓名 | `name` | string | ✅ | input | 必填 ≤20 |
| ② | 来访者电话 | `phone` | string | ✅ | input | 11 位手机号 |
| ② | 与老人关系 | `relation` | string | ✅ | input | 必填 ≤10（儿子/女儿/护工） |
| ② | 来访时间 | `visit_date` | datetime | ✅ | DateTimePicker | 默认 now |
| ② | 来访人数 | `visit_num` | int | ✅ | stepper | 1~20，默认 1 |

### 3.4 详情/操作状态机
```
在院(visit_flag=0) ──> [登记离开] [编辑] [删除]
已离开(visit_flag=1) ──> [删除]（编辑禁用）
```
- **登记离开**：确认弹窗（`leave_date` 默认 now）→ `recordLeave` → Tag 变灰
- **编辑**：复用新增向导（`getVisitById` 回填，`elder_id` 锁定不可改）→ `editVisit`
- **删除**：二次确认 → `deleteVisit`

## 4. 事故登记（`pages/accident`）
