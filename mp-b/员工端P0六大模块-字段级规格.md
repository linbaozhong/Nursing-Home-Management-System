# 员工端小程序 P0 六大模块 · 字段级细化规格

> 文档版本：v1.1
> 生成日期：2026-08-19
> 适用项目：`mp-b/admin`（微信小程序，uni-app-x）
> 契约依据：`backend/internal/model/dto/*.go`（Go 后端为唯一事实源，字段一律用其 JSON snake_case 名）
> 配套方案：`mp-b/移动端复刻方案-员工端.md`
> 更新：v1.1 新增 **§9 组件契约**（业务组件落位 `admin/components/` + 高阶模板 `ListPage`/`WizardForm`）

## 0. 全局规范

### 0.1 接口约定
| 项 | 约定 |
|---|---|
| BaseURL | `https://<域名>/v1`（Go 路由全带 `/v1` 前缀，**非**老系统 `/api`） |
| 鉴权 | 除 `/account/login`、`/account/sendCode`、`/account/forget` 外全部需 `Authorization: Bearer <token>`（`lib.AuthMiddleware`） |
| 统一响应 | `Result { code:int, msg:string, data:object }`；分页数据在 `data` 内为 `PageResult { page_num, page_size, pages, size, total, list }` |
| 错误 | `code != 0` 时 toast `msg`；`code == 401` 跳登录页 |
| 时间 | `time.Time` → 字符串 `2006-01-02 15:04:05`，移动端展示格式化 `MM-DD HH:mm` |
| 金额 | `types.Money`（`pay_amount`、`price`、`total_amount`、`really_amount` 等）→ JSON 数字（元），前端一律 `¥xx.xx`，禁止 `toFixed` 丢精度，建议分计算/BigInt |
| 分页 | **P0 列表全部取消分页**：请求 `page_num=1&page_size=200`（上限待后端确认），前端本地全量搜索/筛选（见 §7） |

### 0.2 通用组件
> 业务组件全部落位 `admin/components/`（含高阶模板 `high-level/`），props / 事件 / 状态字段级定义见 **§9 组件契约**。本节为速览，契约以 §9 为准。

1. **ListPage 列表页高阶模板**（6 个列表页复用）：搜索 / 筛选区 / 卡片 / 空态 / 下拉刷新 / 上拉加载，见 §9.1
2. **WizardForm 向导高阶模板**（外出/来访/事故/点餐新增复用）：Step 指示器 + 上一步/下一步/提交，见 §9.2
3. **ElderSearch 长者搜索器**（外出/来访/事故/点餐/档案共用）
   - 触发：列表页顶部搜索框、或向导 Step1 的"选择老人"入口
   - 数据源：`GET /elderRecord/pageSearchElderByKey`（分页 200，本地过滤）
   - 弹层半屏：搜索框（`name`）+ 列表项 `[姓名] 身份证尾4位 / 电话 / 入住状态`
   - 返回选中对象 `{ id, name, id_num, sex, phone, address, check_flag }`，契约见 §9.3
4. **StaffSearch 员工搜索器**（事故-护工、送餐人员）
   - 数据源：`GET /reserve/pageSearchStaffByKey`（`{page_num,page_size,name?,phone?}` → `{id,name,phone}`）
   - 送餐人员另可用无参全量 `GET /nurseReserve/listNurseStaff` → `{id,name,phone}`
   - 契约见 §9.4
5. **DateTimePicker**：`picker mode="date"` + `mode="time"` 组合，输出 `yyyy-MM-dd HH:mm`；仅"发生时间/外出时间"等历史时间允许过去，计划返回时间校验 > 外出时间，契约见 §9.5
6. **ImageUploader 图片上传**：`uni.chooseMedia`（最多 9 张）→ `POST /file/uploadImage`（FormData `file`）→ 存返回 URL 字符串；支持预览/删除，契约见 §9.5
7. **StatusTag 状态标签**：色板见各模块与 §9.6
8. **DishesPicker 菜品选择器**（点餐）、**ContactQuickFill 联系人快捷填充**（外出）、**SectionCard 详情分区块**：见 §9.7~§9.9

## 1. 登录与权限（`pages/login`、`pages/mine`）

### 1.1 页面
- `pages/login/login`：手机号 + 密码（暂不做验证码登录 UI，`sendCode` 留接口）
- `pages/mine/index`：头像/姓名/手机号/退出
- `pages/mine/edit-pass`：修改密码

### 1.2 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/account/login` | POST | `{ phone*, pass* }` | `LoginUserVO { id, name, avator, phone, pass, auth_id_list[], auth_url_list[], token }` |
| `/account/edit` | POST | `{ id*, old_pass*, new_pass* }` | `EmptyResp` |
| `/account/sendCode` | POST | `{ phone* }` | `EmptyResp`（备用） |
| `/account/logout` | GET | `-` | `EmptyResp` |

### 1.3 权限映射（auth_url_list 驱动，已固化）
- 登录成功后本地持久化 `token`、`name`、`auth_id_list`、`auth_url_list`
- 首页工作台功能入口 / 模块 **按 `auth_url_list` 显隐**（已从后端 `auth` 表固化）：

| 模块 | 权限 url（后端 auth.url） | 前端 ModuleKey | 落地 |
|---|---|---|---|
| 长者档案 | `/people/old` | `elder` | TabBar / 工作台 |
| 外出登记 | `/check-in/leave` | `leave` | TabBar / 工作台 |
| 来访登记 | `/check-in/visit` | `visit` | 工作台入口 |
| 事故登记 | `/check-in/accident` | `accident` | 工作台入口 |
| 点餐 | `/food/order` | `order` | TabBar / 工作台 |

- 前端实现：`utils/auth.ts` 的 `canAccess(module)`（`auth_url_list` 精确匹配）+ `accessibleModules()` 过滤；`pages/index` 工作台按权限渲染入口；无权限时显示"暂无可用功能权限"。
- 注意：uni-app-x **原生 tabBar 无法登录后动态增删**，故 TabBar 4 项固定（档案/外出/点餐/我的），来访/事故作为工作台功能入口（`navigateTo`）按权限显隐。

## 2. 外出登记（`pages/leave`）

### 2.1 页面结构
| 页面 | 路径 | 说明 |
|---|---|---|
| 列表 | `pages/leave/list` | 全量加载 + 本地筛选 |
| 新增向导 | `pages/leave/edit` | 2 步：①选老人 ②陪同人+时间 |
| 详情/操作 | `pages/leave/detail` | 状态化按钮区 |

### 2.2 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/outward/pageOutwardByKey` | GET | `page_num,page_size,elder_name?,chaperone_type?,start_time?,end_time?` | 分页 `list[] = PageOutwardByKeyVO` |
| `/outward/addOutward` | POST | `AddOutwardQuery` | `EmptyResp` |
| `/outward/getOutwardById` | GET | `{ id }` | `GetOutwardByIDVO` |
| `/outward/editOutward` | POST | `EditOutwardQuery` | `EmptyResp` |
| `/outward/delayReturn` | POST | `{ id*, plan_return_date* }` | `EmptyResp` |
| `/outward/recordReturn` | POST | `{ id*, real_return_date* }` | `EmptyResp` |
| `/outward/deleteOutward` | POST | `{ id }` | `EmptyResp` |

**PageOutwardByKeyVO**：`id, elder_name, chaperone_name, chaperone_phone, chaperone_type, outward_date, plan_return_date, real_return_date`
**GetOutwardByIDVO**：`id, elder_name, chaperone_name, chaperone_phone, chaperone_type, outward_date, plan_return_date`
**AddOutwardQuery**（编辑=同字段+`id`）：`elder_id*, chaperone_name*, chaperone_phone*, chaperone_type*, outward_date*, plan_return_date*`

### 2.3 列表页
- **搜索区**：老人姓名输入框（本地过滤 `elder_name`）
- **筛选**：`chaperone_type` 分段器 `全部 / 护工 / 家属`；时间范围（可选，本地过滤 `outward_date`）
- **卡片**（一行一卡）：
  - 左侧：`老人姓名`（加粗）+ 状态 Tag
  - 右侧：`外出时间` → `计划返回时间`
  - 底部：`陪同人：xxx(家属/护工) · 138xxxx`，未返回且超时的显示红色"已超时"角标
- **状态派生逻辑**（后端不返回状态字段，前端本地推导）：

| 状态 | 判定 | Tag 色 |
|---|---|---|
| 外出中 | `real_return_date` 为空且未超时 | 蓝 |
| 已超时 | `real_return_date` 为空且 `now > plan_return_date` | 红 |
| 已返回 | `real_return_date` 非空 | 绿 |
- **空态**：无数据 → 插画 + "暂无外出记录" + 去登记按钮

### 2.4 新增向导（2 步）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ①选老人 | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ②陪同人 | 姓名 | `chaperone_name` | string | ✅ | input | 必填 ≤20 字 |
| ②陪同人 | 电话 | `chaperone_phone` | string | ✅ | input type=number | 11 位手机号 |
| ②陪同人 | 类型 | `chaperone_type` | string | ✅ | radio | 枚举 `护工/家属` |
| ②时间 | 外出时间 | `outward_date` | datetime | ✅ | DateTimePicker | 必填 |
| ②时间 | 计划返回 | `plan_return_date` | datetime | ✅ | DateTimePicker | 必填，> outward_date |

- 陪同人**快捷填充**：已选老人的紧急联系人列表（复用 `/elderRecord/pageSearchEmergencyContactByKey?elder_id=`），点击自动回填姓名/电话并置 `chaperone_type=家属`（见 §7 复用说明）
- 提交：`addOutward` → 成功提示 → 返回列表刷新（新记录置顶）

### 2.5 详情/操作状态机
```
已返回(real_return_date!=空) ──> 仅"删除"可操作
外出中 ──> [延期返回] [登记返回] [删除]
```
- **延期返回**：弹窗 DateTimePicker（新 `plan_return_date`，默认当前时间+1h，必须晚于原计划）→ `delayReturn`
- **登记返回**：确认弹窗"确认该老人已返回？"（时间默认 now，可改）→ `recordReturn`
- **删除**：二次确认弹窗 → `deleteOutward`；删除后卡片消失

## 3. 来访登记（`pages/visitor`）

### 3.1 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/visit/pageVisitByKey` | GET | `page_num,page_size,elder_name?,visit_name?,visit_phone?,visit_flag?` | 分页 `list[] = PageVisitByKeyVO` |
| `/visit/addVisit` | POST | `AddVisitQuery` | `EmptyResp` |
| `/visit/getVisitById` | GET | `{ id }` | `GetVisitByIDVO` |
| `/visit/editVisit` | POST | `EditVisitQuery` | `EmptyResp` |
| `/visit/recordLeave` | POST | `{ id*, leave_date* }` | `EmptyResp` |
| `/visit/deleteVisit` | POST | `{ id }` | `EmptyResp` |

**PageVisitByKeyVO**：`id, elder_name, visit_name, visit_phone, relation, visit_date, leave_date, visit_num, visit_flag(*int8: 0-在院/1-已离开)`
**GetVisitByIDVO**：`id, elder_name, visit_name, visit_phone, relation, visit_date, visit_num`（无 `leave_date/visit_flag`）
**AddVisitQuery**（编辑=同字段+`id`）：`elder_id*, name*, phone*, relation*, visit_date*, visit_num*`

### 3.2 列表页
- **搜索**：老人姓名（本地过滤 `elder_name`）
- **筛选**：`visit_flag` 分段器 `全部 / 在院(0) / 已离开(1)`——后端筛选直接传 `visit_flag`
- **卡片**：
  - 头部：`老人姓名` + Tag（在院=绿 / 已离开=灰）
  - 主体：`来访者：姓名(关系) · 138xxxx`；`人数 xN`
  - 底部：`来访时间`（已离开时追加 `离开时间`）
- **列表页快捷操作**：未离开卡片提供 `[登记离开]` 按钮（列表页直达，不必进详情）

### 3.3 新增向导（2 步）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ① | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ② | 来访者姓名 | `name` | string | ✅ | input | 必填 ≤20 |
| ② | 来访者电话 | `phone` | string | ✅ | input | 11 位手机号 |
| ② | 与老人关系 | `relation` | string | ✅ | input | 必填 ≤10（儿子/女儿/护工） |
| ② | 来访时间 | `visit_date` | datetime | ✅ | DateTimePicker | 默认 now |
| ② | 来访人数 | `visit_num` | int | ✅ | stepper | 1~20，默认 1 |

### 3.4 详情/操作状态机
```
在院(visit_flag=0) ──> [登记离开] [编辑] [删除]
已离开(visit_flag=1) ──> [删除]（编辑禁用）
```
- **登记离开**：确认弹窗（`leave_date` 默认 now）→ `recordLeave` → Tag 变灰
- **编辑**：复用新增向导（`getVisitById` 回填，`elder_id` 锁定不可改）→ `editVisit`
- **删除**：二次确认 → `deleteVisit`

## 4. 事故登记（`pages/accident`）

### 4.1 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/accident/pageAccidentByKey` | GET | `page_num,page_size,elder_name?,staff_name?` | 分页 `list[] = PageAccidentByKeyVO` |
| `/accident/addAccident` | POST | `AddAccidentQuery` | `EmptyResp` |
| `/accident/getAccidentById` | GET | `{ id }` | `GetAccidentByIDVO` |
| `/accident/editAccident` | POST | `EditAccidentQuery` | `EmptyResp` |
| `/accident/deleteAccident` | POST | `{ id }` | `EmptyResp` |

**PageAccidentByKeyVO**：`id, elder_name, staff_name, occur_date`
**GetAccidentByIDVO**：`id, elder_name, staff_id, occur_date, description, picture`
**AddAccidentQuery**（编辑=同字段+`id`）：`elder_id*, staff_id*, occur_date*, description*, picture*`

### 4.2 列表页
- **搜索**：老人姓名（本地过滤 `elder_name`）
- **卡片**：`老人姓名` + `护工：xxx` + `发生时间`；红"事故"Tag；**列表页可本地筛 `staff_name`**
- 默认按 `occur_date` 倒序

### 4.3 新增向导（3 步，全量字段见 AccidentQuery）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ① | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ① | 护工 | `staff_id` | int64 | ✅ | StaffSearch（`pageSearchStaffByKey`） | 必选 |
| ② | 发生时间 | `occur_date` | datetime | ✅ | DateTimePicker | 默认 now，不允许未来 |
| ③ | 事故描述 | `description` | textarea | ✅ | textarea | 必填 ≤500 字 |
| ③ | 事故图片 | `picture` | string(URL) | ✅ | ImageUploader | **至少 1 张**；`uni.chooseMedia` → `/file/uploadImage` 返回 URL 后提交 |

> ⚠️ 后端 `picture` 为**单个字符串**（`valid:"required"`）：若多图需"多张拼接（逗号/竖线分隔）"或仅取首图——**需后端确认**；规格暂定 1 张必填 + 最多 9 张拼接，展示时按分隔符拆分。

### 4.4 详情/操作
- 详情：老人/护工/发生时间 + 图片九宫格预览（`previewImage`）+ 描述全文
- 操作：`[编辑]`（回填向导，老人可改）、`[删除]`（二次确认）
- 无状态机（记录型模块）；编辑后列表同步刷新

## 5. 点餐（`pages/order`）

### 5.1 接口契约
| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/order/pageOrderByKey` | GET | `page_num,page_size,elder_name?,elder_phone?` | 分页 `list[] = PageOrderByKeyVO` |
| `/order/addOrder` | POST | `AddOrderQuery` | `EmptyResp` |
| `/order/getOrderById` | GET | `{ id }` | `GetOrderByIDVO` |
| `/order/sendOrder` | POST | `{ id*, staff_id*, deliver_dishes_date* }` | `EmptyResp` |
| `/dishes/pageDishesByKey` | GET | `page_num,page_size,type_id?,dishes_name?` | 分页 `list[] = PageDishesByKeyVO` |
| `/nurseReserve/listNurseStaff` | GET | 无参 | `[] = { id, name, phone }` |

**PageOrderByKeyVO**：`id, elder_name, elder_phone, dine_date, dine_type, staff_name, deliver_dishes_date, pay_amount(Money), order_flag(string: "是"=已送餐/"否"=待送餐)`
**GetOrderByIDVO**：`elder_name, elder_phone, dine_date, dine_type, staff_name, deliver_dishes_date, order_dishes_vo_list[]`
**OrderDishesVO**：`dishes_name, dishes_price(Money), order_num, set_flag, total_amount(Money), really_amount(Money)`
**AddOrderQuery**：`elder_id*, dine_date*, dine_type*, order_dishes_list*[] = { dishes_id*, order_num* }`
**PageDishesByKeyVO**：`id, type_name, dishes_name, price(Money)`

### 5.2 列表页
- **搜索**：老人姓名 / 电话（本地过滤）
- **筛选**：`order_flag` 分段器 `全部 / 待送餐 / 已送餐`（本地过滤；`order_flag="是"→已送餐`）
- **卡片**：
  - 头部：`老人姓名` + Tag（待送餐=橙 / 已送餐=绿）
  - 主体：`堂食/送餐 · MM-DD HH:mm 就餐`；`已点 x 道 · ¥xxx.xx`
  - 底部：已送餐时显示 `送餐人：xxx`；**待送餐 + 送餐方式=送餐**时显示 `[去送餐]` 按钮
- `dine_type` 枚举：`送餐/堂食`；`堂食`订单**不出现送餐按钮**

### 5.3 新增向导（2 步）
| Step | 字段 | JSON | 类型 | 必填 | 组件 | 校验 |
|---|---|---|---|---|---|---|
| ① | 老人 | `elder_id` | int64 | ✅ | ElderSearch | 必选 |
| ① | 就餐时间 | `dine_date` | datetime | ✅ | DateTimePicker | 必填 |
| ① | 就餐方式 | `dine_type` | string | ✅ | radio | `送餐/堂食` |
| ② | 菜品列表 | `order_dishes_list` | array | ✅ | 菜品选择器 | ≥1 项 |
| ② | 菜品项 | `dishes_id` | int64 | ✅ | - | 必填 |
| ② | 份数 | `order_num` | int | ✅ | stepper | 1~99 |

- **菜品选择器**：全量加载 `/dishes/pageDishesByKey` → 左分类右列表（`type_name` 分组），每项 `菜品名 ¥price` + 步进器；底部实时合计 `Σ(price×num)`（本地计算展示，提交金额以服务端 `pay_amount` 为准）
- 提交 `addOrder` → 成功提示 → 返回列表

### 5.4 送餐操作（状态机）
```
待送餐 + 送餐 ──> [去送餐] ──> 选送餐人员(listNurseStaff) + 送餐时间(默认now)
                ──> sendOrder ──> 已送餐(卡片变绿)
待送餐 + 堂食 / 已送餐：无送餐入口
```
- **送餐人员选择**：`GET /nurseReserve/listNurseStaff`（无参全量）弹层列表 `{id,name,phone}` → 提交 `sendOrder`（`staff_id`、`deliver_dishes_date`）
- 点餐模块无删除/编辑操作（P0 范围外，如需删除需后端新增 `deleteOrder`）

## 6. 长者档案（`pages/elder`）

| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/elderRecord/pageElderRecordByKey` | GET | `page_num,page_size,elder_name?,id_num?,elder_sex?` | 分页 `list[] = PageElderByKeyVO` |
