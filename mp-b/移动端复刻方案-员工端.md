## 一、方案概述

员工端小程序服务于院内工作人员的**移动办公**，核心是把 PC 后台中高频、需要"走到哪办到哪"的业务搬到手机上。原则是：

- **不 1:1 复刻 PC 后台**，只保留与现场作业强相关的功能；
- **分页全部取消**（按用户要求），列表改为"全量加载 + 搜索/筛选 + 滚动"，数据量大的模块用"按老人/日期快捷检索"代替翻页；
- **复杂表单拆成多步向导**（Wizard），不再用 PC 弹窗塞全部字段；
- **导航范式**从「左侧树菜单 + 多标签」改为「底部 TabBar + 页面栈 + 顶部 NavBar」；
- **SaaS 多租户**：一个 App 服务多家敬老院企业，用户可「创建企业 / 加入企业 / 切换企业」，业务数据按租户隔离（token 内含租户上下文）。

## 三、交互改造点（员工端）

### 3.1 导航：左侧树 → 底部 TabBar + 工作台宫格
- PC 的左侧多级递归菜单改为 **底部 TabBar（4 项固定：档案 / 外出 / 点餐 / 我的）** + 各页内分组入口。
- 登录后 `reLaunch` 到**工作台 `pages/index`**（非 Tab）：顶部用户卡片（头像/姓名/当前企业名）+ 功能入口宫格。
- 动态权限：登录后根据 `auth_url_list`（`utils/auth.ts` 的 `canAccess`/`accessibleModules`）过滤工作台宫格入口；无权限显示"暂无可用功能权限"。
- 多标签页（TagsView）**直接砍掉**，用小程序原生导航栈替代；顶部 NavBar 用「返回箭头 + 页面标题」替代面包屑。

### 3.2 列表：表格 → 卡片 + 搜索（取消分页）
- 所有 `pageXxxByKey` 的列表，移动端取全量（`page_num=1&page_size=200`），改为「顶部搜索框（按老人姓名/手机号）+ 状态筛选分段器」。
- 每条数据渲染为**卡片**（主信息一行 + 状态标签 + 点击进详情），列表页提供高频快捷操作（如来访"登记离开"）。
- 数据量顾虑：若后端 `page_size` 上限 <200，需放开或确认。

### 3.3 复杂表单：弹窗 → 分步向导
- 外出 / 来访 / 事故 / 点餐新增均复用 **`WizardForm`**（Step 指示器 + 上一步/下一步/提交），每步一屏，父页负责单步校验。
- 「事故登记」含图片：`uni.chooseMedia` 选图 → base64 → `POST /file/uploadImage`。

### 3.4 图片上传（事故登记）
- 调用 `wx.chooseMedia` 选图 → `getFileSystemManager().readFileSync(filePath, 'base64')` → `POST /file/uploadImage`（JSON：`{ module, file: 'data:image/jpeg;base64,...' }`）→ 返回 `{ id, url }`，多张以逗号拼接存入 `picture`。
- 需在小程序后台配置 `request` 合法域名（后端地址）。

### 3.5 床位全景可视化
- PC 是「楼栋树 + 状态色块」。移动端改为 **层级下钻**：楼栋列表 → 楼层 → 房间 → 床位，每级用状态色（空闲/预定/入住/退住审核）标识，替代一屏渲染整棵树。

### 3.6 首页驾驶舱（院长）
- 6 个指标改为**纵向滚动卡片流**；趋势图用 `ucharts`（uni-app 官方推荐，移动端友好），横轴空间受限时做简化。

### 3.7 多租户登录分流（v1.1 新增）
- `uni.login` 取 code → `POST /account/wxLogin` → 按 `need_bind` 分流：
  - 唯一企业已绑定（`need_bind=false`）→ `setLoginUser` 直接进工作台；
  - 多企业（`need_bind=true` 且 `tenants>0`）→ `pages/switch-tenant` 选择；
  - 新用户无企业 → `pages/register` 创建（注册即 30 天免费试用）。
- 账号密码登录 `/account/login` 复用同一分流逻辑；登录页提供"没有企业？立即创建企业"入口。
- 切换企业：`POST /tenant/switchTenant` 重签 token，本地 `current_tenant` 同步；加入企业：`POST /tenant/joinMember`（邀请码）。
- 所有业务接口按当前租户（token 内 `tenant_id`）隔离数据。

## 四、技术栈与目录结构规划

### 4.1 技术栈（实际落地）
- **框架**：uni-app-x（`.uvue` 组件 + `<script setup lang="uts">`），编译到微信小程序；入口 `main.uts`
- **状态管理**：**无 Pinia**——登录态/租户态用本地 Storage 封装 `utils/auth.ts`（`token` / `login_user` / `current_tenant` 三键）
- **网络**：`utils/request.ts`（`uni.request` 封装：统一注入 `Authorization: Bearer <token>`、解析 `Result { code, msg, data }`、`code!=0` toast、`401` 清态跳登录）
- **UI 组件**：`uni_modules/` 官方组件（`uni-nav-bar-x`、`uni-number-box-x`、`uni-badge-view` 等）+ `components/` 业务组件
- **构建**：HBuilderX 运行到微信开发者工具；`pages.json` 路由 + TabBar 配置
- **登录**：微信一键登录为主（`/account/wxLogin`）+ 自研账号密码（`/account/login`）备用

## 五、MVP 落地建议（员工端）

1. **第一步**（已完成）：uni-app-x 骨架 + `request` 封装 + 登录（微信一键 + 账号密码）+ **多租户分流**，跑通"登录 → 选/建企业 → 工作台"。
2. **第二步**（进行中）：交付 P0 的 6 个现场登记/查询模块（长者、外出、来访、事故、点餐），形成可用闭环；补齐 `wizard-form` 组件。
3. **第三步**：补 P1（床位全景、签约向导、退住申请、护理预定、成员管理）。
4. **第四步**：补 P2（驾驶舱、费用、审核）+ 微信绑定增强。
5. **后端需配合**：
   - token 需含租户上下文（格式 `userID[_tenantID[_memberID]]`），旧 token 兼容为平台租户；
   - `/tenant/open|lock` 平台侧开通/锁定租户（试用 30 天后自动锁定）；
   - 列表 `page_size` 放开到 200；`check_flag`/`sex`/`nurse_level` 等字典枚举核对。
