# 敬老院管理系统 · 员工端小程序《移动端复刻方案》

> 文档版本：v1.0
> 生成日期：2026-08-19
> 适用项目：`mp-b`（微信小程序，uni-app + Vue3）
> 目标用户：**敬老院一线工作人员**（护工、营销、院长、财务等）
> 后端：复用现有 `http://<后端>/api/...` 接口，无需改动

---

## 一、方案概述

员工端小程序服务于院内工作人员的**移动办公**，核心是把 PC 后台中高频、需要"走到哪办到哪"的业务搬到手机上。原则是：

- **不 1:1 复刻 PC 后台**，只保留与现场作业强相关的功能；
- **分页全部取消**（按用户要求），列表改为"全量加载 + 搜索/筛选 + 滚动"，数据量大的模块用"按老人/日期快捷检索"代替翻页；
- **复杂表单拆成多步向导**（Wizard），不再用 PC 弹窗塞全部字段；
- **导航范式**从「左侧树菜单 + 多标签」改为「底部 TabBar + 页面栈 + 顶部 NavBar」。

## 三、交互改造点（员工端）

### 3.1 导航：左侧树 → 底部 TabBar
- PC 的左侧多级递归菜单改为 **底部 TabBar（4 项）+ 各 Tab 内的分组宫格**。
- 动态权限：登录后根据 `authIdList` 决定 Tab 与宫格项的显隐（复用 PC 的菜单树权限判断逻辑，仅替换渲染层）。
- 多标签页（TagsView）**直接砍掉**，用小程序原生导航栈替代。
- 顶部 NavBar 用「返回箭头 + 页面标题」替代面包屑。

### 3.2 列表：表格 → 卡片 + 搜索（取消分页）
- 所有 `pageXxxByKey` 的列表，移动端**不传分页参数或取全量**，改为「顶部搜索框（按老人姓名/手机号）+ 状态筛选抽屉」。
- 每条数据渲染为**卡片**（主信息一行 + 状态标签 + 点击进详情），长按/右滑出操作（编辑、删除、登记返回等）。
- 数据量顾虑：若后端不支持取消分页，则移动端默认取较大单页（如 `size=200`）并前端做本地搜索；后续建议后端加"不分页全量"接口。

### 3.3 复杂表单：弹窗 → 分步向导
以「入住签约」为例（PC 用 6 个子组件在一个弹窗内）：
1. 选择老人（搜索）→ 2. 选择床位（楼栋树点选）→ 3. 选护理等级 → 4. 选餐饮套餐 → 5. 紧急联系人 → 6. 确认提交。
- 每步一屏，底部「上一步 / 下一步」，最后一步提交 `checkContract.addCheckContract`。
- 「事故登记」含图片：用 `uni.chooseImage` / `uni.uploadFile` 替代 PC 的 `<input type=file>`。

### 3.4 图片上传（事故登记）
- 调用 `wx.chooseMedia` 选图 → `uni.uploadFile` 上传，拿到 URL 回传 `accident.addAccident`。
- 需在小程序后台配置 `uploadFile` 合法域名（后端地址）。

### 3.5 床位全景可视化
- PC 是「楼栋树 + 状态色块」。移动端改为 **层级下钻**：楼栋列表 → 点击进楼层 → 房间 → 床位，每级用状态色（空闲/预定/入住/退住审核）标识，替代一屏渲染整棵树。

### 3.6 首页驾驶舱（院长）
- 6 个指标改为**纵向滚动卡片流**；趋势图用 `ucharts`（uni-app 官方推荐，移动端友好），横轴空间受限时做简化。

## 四、技术栈与目录结构规划

### 4.1 技术栈
- **框架**：uni-app（Vue3 + `<script setup>` + TS）
- **状态管理**：Pinia（`auth` 存 token/用户信息/`authIdList`，`user` 存当前操作上下文）
- **网络**：`uni.request` 二次封装（统一注入 token、解析 `code`），替代 PC 的 axios
- **UI 组件**：`uni-ui` 基础组件 + 少量自定义（卡片、状态标签、向导步骤条）；图表用 `ucharts`
- **构建**：HBuilderX 或 CLI（`npm run dev:mp-weixin`），未来 `npm run build:app` 打包 App
- **登录**：保留 PC 的自研账号密码体系（`/api/account/login`），暂不用微信授权（避免与现有账号体系冲突）；后续可加"微信绑定"增强体验

## 五、MVP 落地建议（员工端）

1. **第一步**：搭 uni-app 骨架 + `request` 封装 + 登录 + Pinia 权限，跑通"登录→工作台"。
2. **第二步**：交付 P0 的 6 个现场登记/查询模块（长者、外出、来访、事故、点餐），形成可用闭环。
3. **第三步**：补 P1（床位全景、签约向导、退住申请、护理预定）。
4. **第四步**：补 P2（驾驶舱、费用、审核）+ 微信绑定登录。
5. 后端需配合：确认登录接口返回的 `authIdList` 字段、为移动端放开或不限制列表分页。

> 注意：PC 端 `getRouterTree` 当前走 mock，真实后端接入时需确保小程序也走 `/api/account/login` 返回的 `authIdList` 来动态控权，与 PC 保持一致。
