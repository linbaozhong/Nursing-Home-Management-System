# 敬老院管理系统 · 前端项目分析报告

> 生成日期：2026-08-18
> 技术栈：Vue 3 + Vue Router 4（hash 模式）+ Vuex + Element Plus + TypeScript + Vite
> 说明：本系统为**动态菜单 + 权限路由**架构，左侧菜单由后端（当前为 `src/mock/routes.ts` 模拟）按 `authIdList` 权限过滤后返回，前端按 `pid` 父子关系构造成树，再动态注册路由。

---

## 一、整体架构与页面联系

### 1.1 入口与路由机制

- `src/router/index.ts`：仅定义**静态路由**——根布局 `Layout`（`/` → 重定向 `/home`）、登录页 `/login`、404 兜底 `/:pathMatch(.*)*`。
- `router.beforeEach` 守卫逻辑：
  1. 白名单 `/login` 直接放行；
  2. 无 `token` → 跳登录；
  3. 有 `token` 但未初始化动态路由 → 调用 `initRoutes()`（内部 `store.dispatch("app/getRouterTree")` + `formatRouteTree` 构树 + 动态 `addRoute`）；
  4. 正常放行。
- `src/store/modules/app/index.ts`：
  - `actionLogin` → 调用 `getLogin` 登录，存入 `token`、用户信息（含 `authIdList`）；
  - `getRouterTree` → **当前实现走 mock**（`getRouterList` 从 `mock/routes.ts` 过滤 `authIdList`）生成菜单树，置 `hasAuth=true`；
  - `logout` → 清空 store/localStorage，清除动态路由，回登录页。
- `src/mock/routes.ts`：完整菜单定义（id / pid 父子结构），是页面与菜单联系的**权威来源**（见附录 A）。

> 注意：代码中 `getRouterTree` 当前调用的是 mock 而非真实后端（`import { getRouterList } from '@/mock/getters'` 已启用，`getUserRouteList` 被注释）。接入真实后端时，应改为调用 `/api/...` 权限接口（如 `src/apis/user.ts` 的登录返回 `authIdList`），并把 `getRouterList` 替换为真实请求。

### 1.2 三层布局（Layout）与页面承载关系

所有业务页面均嵌在 `src/layout/index.vue` 提供的统一框架内：

```
Layout（布局容器，含 <router-view/>）
├── components/SideBar/index.vue   左侧菜单（递归 MenuItem 渲染权限菜单树）
│     └── components/SideBar/components/MenuItem.vue  菜单项（递归，支持多级）
├── components/NavBar/index.vue     顶部栏（面包屑 / 用户下拉：修改密码、退出登录）
│     ├── 用户头像 + 用户名
│     ├── 修改密码弹窗（editPass → /api/account/edit）
│     └── 退出登录（logout → /api/account/logout）
└── components/Tags/index.vue       多标签页（打开的页面历史，可关闭/跳转）
```

业务页面通过 `meta.title` 渲染菜单与标签；`App.vue` 在外层包裹 `el-config-provider`（中文）并加了错误边界（`onErrorCaptured` + 重试按钮）。

### 1.3 页面间跳转关系（业务流）

```
登录页 /login
   │ (登录成功，拿到 token + authIdList)
   ▼
首页 /home ──────────────┐（数据概览，可下钻到各业务）
   │
   ├─ 营销管理 /sale ────► 咨询管理 /sale/counsel ──(转为意向)──► [意向客户(已注释未启用)]
   │                   └─► 预定管理 /sale/book
   │
   ├─ 入住管理 /live ────► 床位全景 /live/bed
   │                   ├─► 入住签约 /live/enter
   │                   ├─► 外出登记 /live/leave
   │                   ├─► 来访登记 /live/visitor
   │                   ├─► 事故登记 /live/accident
   │                   └─► 退住申请 /live/apply
   │
   ├─ 人员管理 /people ──► 长者档案 /people/old
   │                   └─► 员工管理 /people/staff
   │
   ├─ 服务管理 /serve ──► 服务项目 /serve/project
   │                   ├─► 护理等级 /serve/level
   │                   └─► 服务预定 /serve/book
   │
   ├─ 餐饮管理 /diet ───► 菜品管理 /diet/dish
   │                   ├─► 餐饮套餐 /diet/package
   │                   └─► 点餐 /diet/order
   │
   ├─ 费用管理 /charge ─► 预存充值 /charge/prestore
   │                   ├─► 消费记录 /charge/record
   │                   └─► 退住审核 /charge/audit ──(审核通过)──► 释放床位

   └─ 基础配置 /base ───► 营销/来源渠道 /base/sale/origin

（资源物资管理 /resource 整块已在 mock 中注释，未启用）
```

> 关键业务闭环：营销（咨询→预定）→ 入住（签约选床位+护理等级+餐饮套餐）→ 日常（外出/来访/事故/餐饮/服务）→ 退住（申请→费用审核→释放床位）。

## 二、各页面意图（含子组件）

> 以下“容器页”指 `xxx/index.vue`，其内部 `<router-view/>` 仅承载子路由，本身无业务表单；“功能页”为具体业务列表/表单页。

### 2.1 登录页 `views/login/`
- **意图**：账号登录、发送验证码、忘记密码、修改密码入口。
- **子组件**（`login/components/`）：
  - `LoginModel.vue`：登录表单（手机号+密码），提交 `getLogin`；
  - `CodeLogin.vue`：验证码登录（发送 `sendCode`）；
  - `ForgetModel.vue`：忘记密码（`forgetPass`）；
  - `EditPass.vue`：修改密码（`editPass`）；
  - `SwiperModel.vue` / `SwiperModelItem.vue`：登录页背景轮播。
- **调用的 API**：`user.ts`（getLogin / sendCode / forgetPass / editPass / getLogout）。

### 2.2 首页 `views/home/`（路径 /home）
- **意图**：运营数据驾驶舱，聚合展示关键指标。
- **子页面/组件**：
  - `index.vue`：容器，组合下方卡片；
  - `todayOverview.vue`：今日概览（getTodayOverview）；
  - `todaySold.vue`：今日销售跟进（getTodaySaleFollow）；
  - `todayFollow` 同类：`monthPerformance.vue`：本月业绩排行（getMonthPerformanceRank）；
  - `clientSource.vue`：客户来源渠道（getClientSource）；
  - `soldBed.vue` / `trend.vue`：可售床位（getAvailableBed）/ 业务趋势（getBusinessTrend）。
- **调用的 API**：`home.ts` 全部 6 个接口。

### 2.3 营销管理 `views/sale/`（路径 /sale，重定向 /sale/counsel）
- **容器页** `sale/index.vue`：仅 `<router-view/>` + 分类标签。

  - API：`bookManage.ts`（reserve 系列）。

## 四、关键设计说明

1. **权限路由（动态）**：菜单与可访问路由由 `authIdList`（登录返回）驱动；当前走 `mock/routes.ts`，接入真实后端时应改为请求 `/api/...` 权限接口。
2. **统一 CRUD 模式**：绝大多数模块遵循 `pageXxxByKey`(列表) + `addXxx` + `getXxxById` + `editXxx`(PUT) + `deleteXxx`(DELETE) 的 RESTful 风格，并对表单字段做 `Reflect.has` 适配（后端返回字段名与前端 prop 不一致时做映射）。
3. **跨模块复用**：`pageSearchElderByKey`（搜索老人）在 `bookManage/checkContract/outward/visit/accident/retreatApply/nurseReserve/order/depositRecharge/intention` 中重复出现；楼栋树 `getBuildTree` 在 `reserve` 与 `checkContract` 中复用；说明“老人/楼栋”是基础主数据。
4. **状态层**：Vuex 模块 `app`（token/菜单/用户）、`tagsView`（多标签）、`user` 等；`http.ts` 统一注入 token 与 `code` 判断。
5. **未启用部分**：`/resource`（物资管理，6 个子页）、`sale/intention`（意向客户独立页）、`people/activity`、`base/activity`、`base/sale/tag` 在 `mock/routes.ts` 中以注释形式存在，对应视图组件已存在但未挂入菜单。
